## High

### H1. A kill that failed is reported as done on retry (fixed `228355c`)

- **Where:** `predcup/app.py:239-247` (`App._do_kill`).
- **What:** `_halt_handled` was set before `RiskManager.kill()` ran. If the kill
  raised (venue unreachable), `KillFileWatcher` retried on its next poll, as
  designed, but `_do_kill` returned a synthetic `success=True` result without
  cancelling, and the watcher marked itself done. A second Telegram `/kill`
  also did nothing. A kill that left orders open was cached and never retried.
- **Effect:** "kill means no open orders" silently broken exactly when the
  venue is flaky.
- **Fix:** remember only a verified-clean kill; a kill that raised or left
  orders open runs again on the next request. Concurrent kills are serialized
  with a lock.
- **Tests:** `tests/test_app_safety.py::test_kill_that_raised_is_retried_by_the_next_kill`,
  `test_kill_file_watcher_retries_until_orders_are_gone`,
  `test_failed_kill_result_is_retried_not_cached`, `test_successful_kill_is_not_repeated`.

### H2. Orders can be posted, or left resting, after a kill (fixed `e36f1bf`)

- **Where:** `predcup/orders.py:166-189` (batch loop in `requote`), `predcup/app.py` (`_do_kill`).
- **What:** the router risk-checks and records a re-quote's orders, then awaits
  `place_batch`. The halt was checked once, at the start. A kill landing during
  that await (KILL file, `/kill`, reconciliation mismatch) ran its tournament
  cancel-all before the batch reached the venue, so the batch rested after a
  "clean" kill; later chunks of the same re-quote were still sent.
- **Effect:** live orders after a kill, until their 30 s expiry. Breaks hard
  rule 7.
- **Fix:** the router checks the halt (control or the risk kill latch) before
  every chunk; if a halt arrived while a batch was in flight, it cancels the
  orders that just landed, by id. The kill path then waits (bounded,
  `kill_switch.wait_for_inflight_seconds`, 30 s) for the in-flight re-quote to
  finish and runs the kill switch again if anything reached the venue meanwhile.
- **Tests:** `tests/test_order_router.py::test_halt_during_a_batch_stops_later_chunks_and_cancels_what_just_landed`,
  `tests/test_app_safety.py::test_kill_during_an_in_flight_batch_leaves_no_open_orders`
  (a venue that blocks inside `place_batch` while the kill runs).

### H3. Short-YES exposure counted at `price` instead of `1 - price` (fixed `1c32030`)

- **Where:** `predcup/risk.py:277-279` (`_order_notional`).
- **What:** every order's notional was `quantity × price`. Selling YES at `p` is
  buying NO at `1 - p` and ties up `1 - p` a share. Selling a 0.05 longshot
  counted 0.05 a share instead of 0.95.
- **Effect:** a 19× undercount on the order-size, per-market, total and R-vs-D
  caps for exactly the longshot-selling strategy (#3). Positions were already
  correct (`PositionExposure.notional`), orders were not.
- **Fix:** long-YES orders count `p`, short-YES (and NO buys) count `1 - p`,
  market orders the full quantity.
- **Tests:** `tests/test_risk_notional.py`.

### H4. Daily loss stop can never trigger; bankroll never updated (fixed `54e32d3`)

- **Where:** `predcup/risk.py:563` (check), nothing called `update_daily_pnl()` or
  `update_bankroll()` anywhere.
- **What:** `_daily_realized_pnl` stayed 0 forever, so the 8% daily loss stop
  (CLAUDE.md risk defaults) was inert; every cap stayed a fraction of the
  starting 100,000 whatever the account did.
- **Fix:** after each clean reconciliation, read
  `GET /tournaments/{slug}/portfolio/pnl?period=day`: `periodPnl` feeds the
  daily loss stop, `totalAccountValue` the bankroll. A null `periodPnl` or a
  failed read changes nothing and is logged (`pnl`, `pnl_read_failed`), never
  read as 0.
- **Open question:** the spec doesn't define the `day` window precisely
  ("snapshot baseline"; leaderboards use 00:00 UTC). Check the first day's
  values against the web UI.
- **Tests:** `tests/test_markouts.py::test_day_loss_beyond_the_stop_blocks_orders` and three more.

## Medium

### M1. 5xx batch items treated as rejected (fixed `46c93c7`)

- **Where:** `predcup/orders.py:199-203`; `predcup/venues/sig.py:213-214` returns a
  partial 207 when retries run out.
- **What:** items still carrying 5xx (e.g. per-item `ORDER_STATUS_UNKNOWN`) after
  the adapter's retries were confirmed REJECTED, freeing their exposure though
  they may be live.
- **Fix:** a 5xx item stays PENDING (counted), is logged as
  `order_status_unknown`, and quoting is suspended until a clean reconciliation.
  429 items (nothing placed, per the spec) are still marked rejected.
- **Test:** `tests/test_order_router.py::test_5xx_item_stays_counted_and_suspends_quoting_until_reconciled`.

### M2. Fill landing mid-reconciliation causes a false mismatch (fixed `4a0acc2`)

- **Where:** `predcup/reconcile.py` `run_once` (fills sync, then positions read).
- **What:** a fill between the two reads is in the venue position but not yet in
  the local one: a mismatch, which in live mode halts and kills. With active
  quoting this will happen.
- **Fix:** on a difference, sync fills and re-read positions once more
  (`reconciliation_recheck`); declare a mismatch only if it persists.
- **Tests:** `tests/test_reconcile.py::test_fill_landing_mid_reconciliation_is_not_a_mismatch`,
  `test_persistent_mismatch_still_halts_after_the_recheck`.

### M3. Non-numeric `Retry-After` crashes a request mid-retry (fixed `3d56772`)

- **Where:** `predcup/venues/sig.py:188`.
- **What:** `float(Retry-After)`. The spec doesn't fix the format; HTTP allows a
  date. A date, junk or a negative number raised `ValueError` inside the retry
  loop, escaping mid-order with the outcome unknown to the router.
- **Fix:** only a non-negative number of seconds is honoured; otherwise the
  normal exponential backoff.
- **Test:** `tests/test_sig_venue.py::test_unparseable_retry_after_falls_back_to_backoff`.

## Low (not fixed: proposals)

- **L1. Any non-open order result is labelled FILLED** (`predcup/venues/sig.py:279`).
  An order that ends without filling (`terminalReasonCode` SelfTradePrevented,
  Expired) is labelled FILLED. Conservative: it keeps counting until positions
  are known, then drops out. *Proposed:* use `quantityTraded` /
  `terminalReasonCode` to tell filled from terminal-unfilled.
- **L2. The router doesn't itself refuse orders without `expirationDate`.** Hard
  rule: every resting quote has a short expiry. Today the quoter and the test
  script always set one; nothing enforces it at the router. *Proposed:*
  `OrderRouter` refuses any order with `expiration_date is None` (defence in
  depth, one line plus a test).
- **L3. Market orders (no price) are representable end to end**
  (`Order.price=None` → `sig.py:254` sends no price). No code path creates
  them. *Proposed:* the router refuses `price is None`.
- **L4. `Retry-After` honoured uncapped** (`predcup/venues/sig.py:170-172`). A large
  value parks the quoter loop that long. Correct per the rule "always honour
  it"; with H2 the kill no longer waits on it beyond 30 s. *Proposed:* leave,
  but alert when a Retry-After exceeds, say, 60 s.
- **L5. Price normalization of fills and open orders is unconfirmed**
  (`predcup/venues/sig.py:480` fill price, `:422-427` `priceLimit`, both
  `TODO(api)`). Markouts and the fill sign convention depend on it. Go-live
  gate (f) checks it with a manual round trip.
- **L6. Telegram startup errors not verified token-free.** The SIG key travels
  only in the `Authorization` header (never a URL, never logged); httpx INFO
  logging is muted (`predcup/alerts.py:44`); our own handlers log exception
  types only. But an exception from python-telegram-bot during `bot.start`
  (`predcup/main.py:149`) prints a traceback to the journal, and I haven't
  verified that no such message includes the token. *Proposed:* check
  `journalctl -u predcup` after the first VM start, including a deliberately
  wrong token once.
- **L7. `place_test_order` doesn't handle `OrderStatusUnknown`**
  (`predcup/orders.py:269`). The exception reaches the script as a traceback.
  The order is still risk-tracked and `bot_status` shows any open order.
  *Proposed:* catch it in the script and print "check with
  `scripts.bot_status`".

## Checked and clean

- **Bypassing `risk.check()`:** only `OrderRouter` calls `place_order`/`place_batch`
  (`tests/test_order_path.py`, AST). `requote` checks every order; `place_test_order`
  goes through `check_test_order` (all checks but the fair-value band, plus
  1-share/extreme-price limits). No other path.
- **`tournamentId`:** every SIG read and order carries it (order body, cancel-all
  body, `GET /orders`, `/markets`, `/exchanges/*`); fills, positions and P&L use
  the `/tournaments/{slug}/...` paths; `SigVenue` refuses any other tournament id.
  `DELETE /orders/{id}` has no tournament parameter in the spec.
- **Idempotency:** a fresh key per order/batch; retries re-send the identical body
  object; `OrderStatusUnknown` blocks the router instead of re-sending with a new
  key.
- **Retries:** only 429, 503 and 409 `REQUEST_IN_FLIGHT` (plus 502
  `ORDER_STATUS_UNKNOWN` with the same key on order endpoints); other 4xx raise.
- **502 `ORDER_STATUS_UNKNOWN`:** single orders and whole batches retried with the
  same key, then raised; the router keeps the orders counted and suspends
  quoting until reconciliation (per-item case fixed in M1).
- **Ticks:** quoter floors bids / ceils asks to 0.005; `Order` validates on-tick in
  [0.005, 0.995]; the adapter rounds again.
- **Signs:** risk long/short, quoter inventory skew, positions, markouts and fills
  all use the same convention; NO-share exposure uses `1 - price` (orders fixed in
  H3).
- **Expiry:** every quote and test order carries `expirationDate` (see L2 for
  enforcement).
- **Stale state after cancel:** swept quotes stay counted until a clean
  reconciliation; a market still showing orders after its cancel isn't re-posted.
- **Quoter vs kill latch:** fixed in H2.
- **Secrets:** see L6; nothing found that logs the API key or token.
